1项目概述

为什么做、做成什么样、给谁用。

项目定义

Markdown Word 是一个 VS Code 自定义编辑器插件。用户双击打开 .md 文件时，可以像在 Word 中一样：点按钮加粗、拖网格建表格、Ctrl+V 粘贴截图、输入 / 唤出块菜单——而文件本身始终是标准 Markdown 纯文本，可继续被 Git、静态站点、CI 和任何 Markdown 工具消费。

🎯 目标

让不熟悉 Markdown 语法的用户（运营、产品、管理岗）零门槛写 Markdown；让熟练用户获得比 Typora/Notion 更顺手的表格与图片工作流，且不离开 VS Code。

👤 目标用户

① 从 Word/WPS 迁移、被 Markdown 语法劝退的文档作者；② 天天写文档、但受够手敲表格竖线的开发者；③ 需要在文档中高频贴图的技术与设计团队。

💎 核心价值

「按钮能做的事，不要求记语法」。四张王牌：Word 级 Ribbon 界面、可视化表格、粘贴即存的图片、Confluence 式 / 菜单；一个杀手锏：AI 助手——复用 VS Code 里的 GitHub Copilot 登录，/ 唤出写大纲与模板，选中文字即改写润色。

设计原则

  • 纯文本保真 — 磁盘上永远是规范 Markdown；可视化编辑是视图不是格式。任何操作后源码可读、diff 友好。
  • 像 Word 一样可发现 — 所有能力都能从菜单/工具栏找到，快捷键和 / 只是加速器。
  • 模式自由 — 所见即所得 / 源码 / 双屏三模式随时切换，同一文件无缝互通，尊重 VS Code 老用户习惯。
  • 原生融入 — 主题、字体、快捷键体系、自动保存、大纲面板全部跟随 VS Code，不做"插件里的孤岛"。
  • AI 内建、先预览后落盘 — AI 复用 VS Code 已登录的 GitHub Copilot（Language Model API），零二次登录；一切 AI 改写先差异预览，用户确认后才写入磁盘。
  • 持久化优先 — 插入的图片一律落盘为相对路径引用，杜绝会话级临时地址；任何机器、任何时间重开文档，所见即所存。

3功能需求详述

每个模块包含：能力清单与交互约定，末尾附验收要点。

F01

编辑模式与文件管理

P0 · MVP
  • 三种模式 — ① 所见即所得（默认）：Word 式页面化编辑；② 源码模式：等宽字体的纯 Markdown；③ 分屏模式：左侧源码、右侧渲染，双向同步、同步滚动。Ribbon「视图」页与状态栏均可切换。
  • 自动保存 — 跟随 VS Code 原生 files.autoSave 策略；标签页显示脏点 ●，Ctrl+S 立即写盘。
  • 外部修改同步 — 文件被 Git 或其他程序改动时弹提示：「重新加载 / 覆盖保存」，两选一，禁止静默覆盖。
  • 撤销重做 — Ctrl+Z / Ctrl+Y，粒度为语义操作（「插入一行」是一次撤销，不是数十次字符修改）。
  • 大文件保护 — 超过 1MB 或 5 万字的文档提示切换源码模式，避免可视化渲染卡顿。
验收：三模式内容双向一致；外部修改 100% 触发提示；100KB 文档键入无可感知延迟。
F02

文本与行内格式

P0 · MVP
  • 行内格式全家桶 — 粗体 **、斜体 *、删除线 ~~、行内代码 `、高亮 ==（P1）、上标/下标（P1，^ / ~ 扩展语法）。
  • 作用规则 — 有选区时作用于选区；无选式按开关式输入（再按一次或移动光标闭合）。
  • 清除格式 — Ribbon 按钮，一键去除选区全部行内标记；格式刷（P1）复制字符样式。
  • 快捷输入 — Markdown 速记自动转换：输入 **加粗**、`code` 在闭合时渲染为富文本；粘贴的成对标记同样识别。
  • 字体选择（P1 · 用户强调） — Ribbon「字体」组提供西文字体 + 中文字体两个下拉（Word 同款习惯，可搜索、选中即预览）与字号下拉：西文字体管拉丁字符与数字（默认 Segoe UI），中文字体管 CJK 字符（默认微软雅黑），二者组合为回退链 font-family:'Segoe UI','Microsoft YaHei',sans-serif——中英文自动各用其字体、互不干扰；有选区作用于选区、无选区设为全文默认；持久化为带回退链的 HTML 属性，源码模式可见可改；「清除格式」一键移除；导出 PDF 内嵌字体子集，保证他机打开不缺字（选择器见图 UI-07 ④）。
  • 正文字体 ≠ 代码字体（用户强调） — 正文（含标题、表格、引用等）使用上述比例字体组合；代码块与行内代码固定使用独立等宽字体（默认 Consolas，设置 editor.codeFontFamily，见 F09），代码区不继承正文字体设置，确保对齐与可读性。
验收：每种格式均有按钮入口 + 快捷键 + 速记输入三条路径；自选字体保存重开后排版一致，且在未安装该字体的机器上正常回退、PDF 显示正常；保存后源码为标准 Markdown + 受控 HTML 属性。
F03

标题与段落

P0 · MVP
  • 快速样式库 — Ribbon「开始」页横排展示 正文 / H1–H6 缩略样式，光标所在块高亮对应样式（Word 样式库行为）。
  • 快捷输入 — 行首输入 #+空格 变 H1，##+空格 变 H2，以此类推；行首 >+空格 变引用。
  • 升降级 — Tab/Shift+Tab 在标题上切换级别（H2→H3 / H2→H1）。
  • 段落 — Enter 新段落；Shift+Enter 软换行（两个空格 或 \，可配置）。
验收：六种标题 + 正文互转均无损；源码中标题井号层级与界面一致。
F04

列表

P0 · MVP
  • 三种列表 — 无序 -、有序 1.、任务 - [ ]；各配 Ribbon 按钮与斜杠菜单项。
  • 嵌套 — Tab 增加一级缩进、Shift+Tab 减少，最多 6 级；有序列表跨级编号正确续接（1.1 / 1.2）。
  • 续行与退出 — Enter 续新项；空项上再按 Enter 退出列表；Backspace 删除标记转普通段落。
  • 任务勾选 — 点击复选框即切换 [ ] / [x]，源码同步。
  • 互转 — 选中段落一键转三种列表之一；有序→无序保留层级。
验收：三层嵌套混合列表（有序套任务套无序）编辑、勾选、序列化后 GFM 完全合法。
F05

表格 — 可视化创建与编辑（王牌功能）

P0 · MVP

对标 Word 的「插入 → 表格」体验，同时覆盖 Markdown 表格全部语法（对齐、表头）。

  • 网格选择器创建 — Ribbon「插入 → 表格」下拉 8×6 悬停网格，实时显示「4 × 3 表格」，松开即插入（见图 UI-02）。

  • 入口 — Ribbon「视图 → 页面设置」（下拉快选纸张 + 外观）与完整「页面设置…」对话框；状态栏显示当前纸张（如「A4」/「适应屏幕」），点击直达；设置项 markdownWord.page.* 按工作区持久化。交互见图 UI-09。
  • 与缩放的关系 — 页面尺寸改变纸张宽度（重排），视图缩放（A⁻/A⁺）改变显示比例（不重排），两者独立叠加，与 Word 行为一致。

8技术方案概要

基于现有原型（v0.0.1，Custom Editor + contenteditable）演进，核心风险是「富文本 ↔ Markdown 双向保真」，方案上以成熟编辑器内核收敛自研面。

Webview 编辑器内核ProseMirror（Markdown Schema）React 组件壳Ribbon / 斜杠菜单 / 对话框

数据同步文档 ↔ Webview 双向 patch语义级撤销栈外部修改冲突检测
  • 为何选 ProseMirror — 文档模型天然贴近块/行内结构，markdown 序列化方案成熟（参考 milkdown / tiptap），可将自研范围压缩到「表格交互、图片落盘、Ribbon」等增值层。
  • 图片落盘 — Webview 无磁盘权限，剪贴板图片经 postMessage 传扩展宿主，由 workspace.fs 写入，回传相对路径插入文档。
  • AI 通道 — 经 VS Code Language Model API（vscode.lm.selectChatModels）调用已登录的 GitHub Copilot 模型，复用其认证与配额，插件零密钥零登录；Webview 的 AI 界面通过 postMessage 请求宿主转发，token 流式回传渲染；未登录或企业策略禁用时返回不可用状态，UI 整体优雅降级。
  • PDF 导出 — 宿主侧经打印管线渲染 Webview 快照，内嵌字体子集、打包相对路径图片后输出 PDF，并按标题树生成书签。
  • Draw.io 嵌入（可行性已验证路线） — 打包 Draw.io embed 静态资源（Apache-2.0，与 MIT 兼容）随插件分发，Webview 内以 iframe + postMessage（load / save / exit 协议）驱动就地编辑；保存为 .drawio.svg（XML 内嵌 SVG），以标准图片语法引用——GitHub 原生渲染、可被 vscode-drawio 插件二次编辑；先例：hediet.vscode-drawio 已验证同方案在 VS Code Webview 中稳定可行。查看态用轻量 viewer 渲染，编辑器按需加载以控体积。
  • 性能与内存工程（用户强调 · 指标见第 7 节） — 视口虚拟化 + ProseMirror 增量更新控制 DOM 规模；重型依赖（Draw.io / Mermaid / KaTeX / Shiki 语言包）一律动态 import 按需加载、退出即卸载；图片懒解码；渲染结果 LRU 缓存设上限；撤销栈封顶；关闭标签即销毁 webview；每个里程碑交付时附性能冒烟报告（样例文档关键路径计时 + DevTools 内存快照对比），M3 逐项过堂验收。
  • 与 v0.0.1 的关系 — 保留 Custom Editor 注册与主题变量方案；编辑内核由裸 contenteditable 迁移至 ProseMirror（M0 做往返保真 POC 后再动工）。
